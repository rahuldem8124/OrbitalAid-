## 3. Simulation page (`simulation/page.tsx`)

**Client component** (`"use client"`). Uses `useSearchParams()` to read `conjunctionId`, `assetId`, `threatId` — if present, auto-select "Simulate Maneuver" tab and pre-fill dropdowns.

### Tab structure
Two toggle buttons at top: "New Object Launch" | "Simulate Maneuver". Active tab gets `bg-white/10 border-white/20`, inactive gets `bg-transparent`.

### Tab 1: New Object Launch
Form with 6 fields (all `<input type="number">` in a 2-col grid):
- Mean Motion (revs/day)
- Eccentricity
- Inclination (deg)
- RA of Asc Node (deg)
- Arg of Pericenter (deg)
- Mean Anomaly (deg)

Optional: name field (default "SIMULATED-OBJECT"), bstar (default 0).

"Run Simulation" button → calls `simulateNewObject()`. Loading spinner while in flight.

**Results section**: list of conjunctions found, each row showing object name, miss distance (cyan), TCA, Pc (rose), and `RiskIndicator` badge. Same pattern as `ConjunctionsTableClient.tsx`. Show "No conjunctions found for this object" if `conjunctions_found === 0`.

### Tab 2: Simulate Maneuver
Two `<select>` dropdowns (asset, threat) populated via `fetchObjects()` on mount. A delta-v input (m/s). Pre-selected from URL params if present.

"Run Simulation" button → calls `simulateManeuver()`.

**Before/After comparison** in a side-by-side grid:
- Left column "Current": miss distance, Pc, risk tier (with RiskIndicator)
- Right column "Predicted": new miss distance, new Pc, new risk tier
- Arrow or connector between them
- Color coding: if predicted tier is better (lower risk) → green highlight on predicted side; if same or worse → neutral/red

**Disclaimer note** at bottom of results:
"Estimate uses a simplified linearized model, not a full orbit re-propagation."

## 4. Analytics page (`analytics/page.tsx`)

**Server component** (`"use client"` NOT needed — no interactive state). Uses `Promise.all` to fetch all three endpoints in parallel, same pattern as `src/app/page.tsx`.

### Top disclaimer
Visible note in a `GlassPanel`:
"Showing current snapshot metrics. Trend-over-time analytics (e.g. debris growth) require scheduled recurring screening runs, not yet configured for this deployment."

### Risk Distribution chart
Bar chart using `recharts` `<BarChart>`. Data mapped from the API response `Record<string, number>` to `[{ tier: "critical", count: 5 }, ...]`. Each bar colored to match RiskIndicator: critical=red-500, high=orange-500, watch=yellow-500, low=emerald-400.

### Altitude Distribution chart
Horizontal bar chart using `<BarChart layout="vertical">`. Data from `bins` object — iterate keys directly (don't hardcode bin names). Each bar uses a cyan/purple gradient or single color.

### Response Times
Two stat cards side by side in a `GlassPanel`:
- "Alert Acknowledgement" — avg and median
- "Maneuver Decision" — avg and median

Format seconds → human readable: `< 60s` shows "Xs", `< 3600s` shows "Xm Ys", `≥ 3600s` shows "Xh Ym". If `count === 0`, show "No data yet" instead of duration.
